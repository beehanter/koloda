# Свод правил Kilo Code

Этот документ создан для анализа ошибок, допущенных в проекте "koloda", и для предотвращения их повторения в будущем.

## Глава 1: Стратегическое планирование

1.  **Помни об основной идее (`idea.md`).** Любое действие должно соответствовать конечной цели проекта. Регулярно перечитывай `idea.md`, чтобы не отклоняться от курса.
2.  **Следуй плану (`plan.md`).** Перед решением любой задачи сначала составь подробный план с учетом общего контекста проекта. План — это твоя карта. Не начинай кодировать, не имея четкого пошагового плана.
3.  **Веди дневник (`diary.md`).** Все технические детали, неожиданные проблемы, найденные решения и важные наблюдения должны быть немедленно записаны в `diary.md`. Это твоя база знаний и история проекта. Не держи технические детали в голове.

## Глава 2: Тактическое исполнение

1.  **"Семь раз отмерь" — Глубокий анализ превыше скорости.**
    *   Не доверяй первому впечатлению об ошибке.
    *   Анализируй лог полностью, начиная с **самой первой** ошибки.
    *   Сопоставляй все части системы: исходные данные (CSV), код обработки (Python), схему БД (`init.sql`) и точный SQL-запрос из лога.
    *   Мысленно отлаживай код с реальными данными.

2.  **"Дьявол в деталях" — Внимание к окружению и типам.**
    *   Уважай окружение: помни, что `init.sql` выполняется один раз. Меняешь схему — пересоздавай контейнер с томами (`podman compose down -v`).
    *   Знай свои инструменты: `uv sync`, `uv run`. Не смешивай команды, работающие в разных контекстах.
    *   Опасайся неявных преобразований типов (`numpy` -> `python`). Всегда приводи данные к нативным типам перед передачей в драйвер БД.
    *   Проверяй порядок столбцов.

3.  **"Доверяй, но проверяй" — Изолируй и тестируй.**
    *   Пиши код, готовый к сбоям (`try...except`).
    *   Используй транзакции правильно: одна атомарная операция — одна транзакция с `BEGIN`, `COMMIT` и `ROLLBACK`.
    *   Не предполагай — подтверждай. Используй логирование для проверки своих гипотез.

Следование этим правилам — мой прямой долг для обеспечения качества работы.
